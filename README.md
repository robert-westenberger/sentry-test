# SentryPlayground

A barebones playground for learning Sentry SDK setup. Classic ASP.NET (.NET Framework 4.8.1, `System.Web`) hosts two ASPX pages; each page embeds its own independent React 18 app.

CI builds and uploads the web output only. There is no Sentry release creation or source-map upload anywhere in this repo yet (planned for a later task). Source maps are generated and shipped in the build output.

## Layout

```
SentryPlayground.Web/     SDK-style net481 project; builds into SentryPlayground.Web\bin
  app-one.aspx, app-two.aspx, TestErrorHandler.ashx, Global.asax, Web.config
  static/app-one|app-two/ generated by the frontend builds (git-ignored)
frontend/app-one|app-two/ independent Vite + React + TS packages (IIFE bundle, React included)
scripts/                  stage-web.ps1, start-iisexpress.ps1
.github/workflows/build.yml
```

## Windows prerequisites

- **.NET SDK 9.0.x** (provides `dotnet restore/build`). It builds the net481 project; it does not run it.
- **Node 22** and **pnpm 9.14.3** (`corepack enable` or `npm i -g pnpm@9.14.3`).
- **.NET Framework 4.8.1 runtime** on the machine (built into Windows 11 and Windows 10 22H2 with recent updates; otherwise install it).
- **Reference assemblies for net481.** Compiling needs them. The project references the `Microsoft.NETFramework.ReferenceAssemblies` NuGet package, so you do **not** need the .NET Framework 4.8.1 Developer Pack for `dotnet build`. Install the Developer Pack (or the Visual Studio ".NET Framework 4.8.1 targeting pack" component) only if you want Visual Studio to build/debug the project natively.
- **IIS Express** (installed with Visual Studio's ASP.NET workload, or standalone from Microsoft). It runs classic ASP.NET using the machine's installed .NET Framework. Full IIS also works: enable the ASP.NET 4.8 feature and point a site at the web folder.

## Build

One command that installs and builds everything: `pnpm build:all` (or `.scriptsbuild-all.ps1`). The individual steps:

From the repo root:

```powershell
pnpm install --frozen-lockfile
pnpm -r typecheck
pnpm -r build
dotnet restore SentryPlayground.Web/SentryPlayground.Web.csproj
dotnet build SentryPlayground.Web/SentryPlayground.Web.csproj -c Release --no-restore
```

Frontend output goes to `SentryPlayground.Web/static/app-one` and `.../app-two` (`app.js`, `app.css`, `app.js.map` each). Building one app never clears the other's folder. Compiled assemblies and dependencies land in `SentryPlayground.Web/bin`.

## Run

```powershell
.\scripts\start-iisexpress.ps1            # serves SentryPlayground.Web on port 8080
.\scripts\start-iisexpress.ps1 -Port 9000
```

Optional: `.\scripts\stage-web.ps1` copies a deployable site to `artifacts\web` (the folder CI uploads); you can host that with `-Path artifacts\web`.

- http://localhost:8080/app-one.aspx
- http://localhost:8080/app-two.aspx
- http://localhost:8080/TestErrorHandler.ashx (deliberately throws a backend error)

## Configuring Sentry

With no DSNs, everything builds and runs and Sentry stays disabled. To enable it, copy `SentryPlayground.Web/appSettings.local.config.example` to `appSettings.local.config` (git-ignored) and set your own project DSNs:

| Key | Used by |
| --- | --- |
| `Sentry.Environment` | backend and both frontends |
| `Sentry.Backend.Dsn` | .NET SDK (`Global.asax`) |
| `Sentry.Frontend.Dsn` | both React apps share one Sentry project (written into the page as `window.__SENTRY_CONFIG__`) |

Restart the site after changing it. Events are tagged `app=backend`, `app=app-one`, `app=app-two` (filter or group by the `app` tag in Sentry). Default PII collection is off; no Sentry auth token is used.

## Verifying error capture

1. Set DSNs as above and start the site.
2. Open each app page and click **Throw test error**. The error boundary shows a fallback message; an event tagged `app-one` / `app-two` appears in Sentry.
3. Click **Backend test error** (or open `/TestErrorHandler.ashx`). You get an ASP.NET error page (HTTP 500); one `InvalidOperationException: Synthetic backend test error` event tagged `backend` appears. It is captured once, in `Application_Error`.

Frontend stack traces will be minified until source maps are uploaded (later task).

## Notes

- The `.map` MIME type is declared in `Web.config` so IIS serves source maps.
- SDK-style projects do not generate binding redirects for web apps, so `Web.config` carries them for `System.Memory` and `System.Runtime.CompilerServices.Unsafe`. If you upgrade packages and see `FileLoadException` on startup, update them.
